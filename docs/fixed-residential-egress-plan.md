# 固定住宅出口与订阅切换保护方案

日期：2026-10-27

适用范围：macOS、Clash Verge Rev / Mihomo、Antify、Claude 桌面版与 Claude Code。

状态：设计稿。本文只定义拟实现行为、配置修改建议与验收要求，不表示已安装、已部署或已完成防漏实测。

## 1. 目标与方案选择

采用「一个守护进程 + Clash Verge 配置与全局脚本 + 用户订阅 + Antify」的轻量组合。第一版复用现有 Mihomo 内核，不自研系统网络扩展，不强制新增代理进程或专用监听端口。

| 用户需求 | 目标行为 |
| --- | --- |
| 国内网站正常访问 | 普通国内网站按本地维护的规则直连；保护对象优先于国内规则 |
| 海外网站代理访问 | 非直连目标的 TCP 流量统一走固定住宅出口；不继承订阅的任意 DIRECT 例外 |
| Claude 流量不能漏出 | 已覆盖的 Claude 流量走固定住宅出口；故障时阻断，不切到普通机场或直连 |
| 用户修改或切换订阅 | 重新注入保护规则和固定出口，订阅仅提供允许使用的传输节点；随后验证最终运行配置 |

「流量不漏出」需要分别验收：业务连接未直连、业务 DNS 未绕行、WebRTC/UDP 未暴露非预期公网出口、备用线路未改变出口身份。不能用某一项成功代替其余项目。

本文目标是防止正常使用中的误切订阅和代理故障。主动禁用保护组件、修改管理员级设置、未覆盖的应用、配置重载瞬间及第三方组件缺陷，均需要单独说明边界。

## 2. 组件职责

| 组件 | 职责 | 不能替代的检查 |
| --- | --- | --- |
| 后台公共模板 | 维护规则、DNS、嗅探、协议模板、策略版本 | 不保存公共可见的个人住宅凭据 |
| 用户专属配置 | 保存用户出口绑定与接入信息，由后台生成并私下交付 | 导入成功不代表真实出口正确 |
| 订阅 | 提供传输节点、providers 等可用传输资源 | 不决定最终分流及住宅绑定 |
| 全局扩展脚本 | 注入固定出口、重新生成受控规则与 DNS，避免回环 | 脚本执行成功不代表最终配置未被后续步骤覆盖 |
| Clash Verge | 执行代理、分流、DNS 与按需启用的 TUN | 本地端口可连接不代表已经走住宅出口 |
| Antify | 将指定应用交给本地代理，使用已启用的 Kill Switch 处理不可达 | 不判断住宅出口身份，不能证明业务 DNS 零泄漏 |
| 一个守护进程 | 启动前及运行期核验；异常时阻止或停止受管进程，报告原因 | 周期检查不能代替连接级阻断 |

建议本地混合代理入口使用 `127.0.0.1:7897`。这是客户端代理端口，不是后台订阅下载地址。应同时在 Verge 设置页和 Antify 中保持一致，核验内核实际端口。

## 3. 两种出口拓扑，分别生成脚本

### 3.1 普通机场订阅 + 本地住宅代理：对应现有 v2

```text
普通国内网站 → Mihomo → 国内/私网直连规则 → DIRECT
海外 TCP / Claude → Mihomo → 固定出口 SOCKS5
                            └─ dialer-proxy: 机场前跳
                               → 当前订阅中选定的传输节点
                               → 住宅代理 → 目标网站
受保护应用 → Antify → 127.0.0.1:7897 → 上述固定出口链路
```

`dialer-proxy` 指定连接住宅代理所用的前跳。切换订阅后，只替换可用前跳，住宅代理配置来自用户专属本地设置。[2]

这种方式的用户专属脚本会包含住宅代理地址及认证信息。可以由后台自动生成，免去手填；但不能描述为「客户端没有住宅凭据」。公共模板只保留占位符，专属脚本不得公开。

住宅代理服务器地址不一定等于网站观察到的出口 IP。验收应使用供应商约定、经实际验证的出口身份，不能直接比较两个地址。

### 3.2 我们的托管 WS 订阅 + 服务端住宅绑定

```text
海外 TCP / Claude → 本地固定的用户专属 VLESS + WS + TLS 节点
                  → 我们的服务器 → 用户绑定的住宅代理 → 目标网站
普通订阅切换      → 不替换这个受保护节点及其绑定
```

这种方式的专属脚本保存 VLESS 接入凭据，住宅代理密码只存服务端。不能仅从当前订阅中查找这个节点，必须从独立保存的用户接入配置重新注入。

2026-10-27 已将托管 WS/TLS 入口与独立 3X-UI 同步器部署到当前服务器，并完成同步收据、运行配置和实际出口核验。后台保存用户及住宅绑定，同步器通过本机 3X-UI API 应用受管身份、住宅出口和路由。此结果仅对应已核验的部署；新服务器仍需分别对接，后续变更需重新核对同步状态和实际出口。组件分工见 [服务端说明](../server/README.md#与-3x-ui-的分工与同步)。

两种模式共用规则及 DNS 策略，出口生成部分互斥。不把已经绑定住宅出口的托管节点直接当成普通机场前跳，再串同一住宅代理，避免重复串联及潜在回环。不能只凭节点名识别拓扑，由后台交付的明确模式及接入资料决定。

## 4. 厂商订阅中值得保留和需要调整的内容

用户提供的配置含 Markdown 转义和格式损坏，只作为设计参考。先去掉行尾反斜杠、HTML 空格、链接包装，并恢复正确的 YAML 缩进；不能直接导入原贴文本。

| 配置项 | 处理建议 | 原因 |
| --- | --- | --- |
| `allow-lan: false`、IPv6 关闭、rule 模式 | 保留；核验 Verge 设置页和内核 | 写在订阅里不等于最终采用 |
| `mixed-port: 7890` | 本地约定改为 7897，并同步 Antify | 统一客户端入口，避免误连旧端口 |
| fake-IP、嗅探、`override-destination: false` | 保留并验证 | 帮助域名分流，但不能当成完整防漏证明 |

| `dns.listen: 0.0.0.0:1053` | 建议改成 `127.0.0.1:1053` | 只服务本机；如接管路径要求其他监听方式，再明确配置 |
| `time..com`、`ntp..com` | 删除，按实际需要填明确域名或合法匹配模式 | 当前文本不是预期通配符表达式 |
| nameserver 链接损坏 | 恢复普通 URL 字符串 | 原贴混入 Markdown，不能按有效 YAML 解释 |

| 邮件端口一律 DIRECT | 不作为默认通用规则 | 这会让海外邮件也绕过代理；确有需求时按明确主机例外处理 |
| `skip-proxy` | 不作为保护依据 | 不同客户端支持情况不同；最终以 Mihomo 规则和实际接管为准 |

| 自动切换 | 只在已确认同出口身份的入口间使用 | 普通可达性测试不证明两个节点最终使用同一住宅出口 |
| `tun.enable: false` | 不能据此判定整机受保护 | TUN 是否启用由明确的接管方案和客户端设置决定；仅应用代理不覆盖任意应用 |

WS + TLS 模板使用 `network: ws`、`tls: true`、正确的 servername 及 ws-opts Host/path；不照搬 Vision flow 或 reality-opts。接入参数必须来自真实服务端契约，证书校验保持开启。[7]

## 5. 全局脚本 v2 的审阅结论

### 5.1 保留的部分

- 每次从新的订阅配置收集节点，避免引用上一份订阅的失效节点。
- 重建固定出口和前跳，保护域名规则前置。
- 用 `dialer-proxy` 指定前跳，不把住宅出口和普通机场做可自由切换的最终出口组。
- 对动态 include-all 组排除保护节点，降低回环风险。
- 尝试将节点域名引导解析与业务 DNS 区分。

### 5.2 优先修改的部分

| 位置 | v2 的问题 | v3 建议 |
| --- | --- | --- |
| `directGroup()` / `route()` | 保留任意 DIRECT 例外；原订阅 `MATCH,DIRECT` 也可能保留，海外流量可以直连 | 用本地受控模板生成完整 rules，不逐条改写外部规则 |
| `nativeActions` | 将 PASS 当作可保留的安全终点，不能据此证明后续实际出口 | 删除这套判断；不继承外部 PASS、SUB-RULE 或任意放行组 |
| UDP | 只有固定出口 `udp: false`，不等于拒绝 UDP | 在国内直连规则之前显式拒绝受限 UDP；详见第 6 节 |
| 保护范围 | 只有域名列表，无法证明覆盖未知域名、直接 IP、辅助进程 | 增加经验证的应用进程规则；与 Antify 实际流量识别配合验证 |
| DNS 初始化 | `const dns = config.dns || {}` 在原配置无 dns 时未写回 config | 显式赋值 `config.dns = ...`，无 DNS 时也生成完整对象 |
| `bootstrap()` | 只移除部分路由标记，不能证明余下解析不会循环；未固定业务 DNS | 重建可信引导与业务解析设置，不清洗后继续相信任意继承值 |
| 前跳无静态节点但有 providers | 将 REJECT 放到显式候选中，可能成为默认选中项而妨碍 provider 使用 | 有有效 provider 时不要预置 REJECT 为默认候选；完全无来源时才拒绝 |
| 动态 provider 内容 | 列出 provider 名称不等于其节点已加载、可用或不存在循环依赖 | 运行期确认所选实际节点与依赖链；不满足时不得自动直连 |
| 保留命名空间 | 同名节点和组、重复名称、复杂 dialer 依赖可能造成歧义或回环 | 注入前检查名称唯一性和依赖；只替换明确托管对象，歧义时报错 |
| 全局与订阅扩展顺序 | 全局脚本后仍可能被覆盖 | 生成后检查最终配置，并读取内核验证；错误时拒绝受管启动 |

“脚本抛错”只是错误信号。必须验证目标 Verge 版本如何处理失败：继续旧配置、跳过脚本或拒绝重载，都不能仅凭猜测当成安全状态。

## 6. v3 的规则生成建议

### 6.1 规则来源

使用订阅节点与 providers；rules、sub-rules 及其任意 DIRECT 放行语义不直接继承。用户确有局域网、企业网或特定业务例外时，放入本地显式白名单，保护规则优先。

以下是便于审阅的核心替换片段，不是完整可安装脚本。`exit` 和 `settings.domains` 沿用生成器内部配置，进程规则由实际路径核验后插入：

```javascript
config.rules = [
  'NETWORK,udp,REJECT',
  ...settings.domains.map(host => 'DOMAIN-SUFFIX,' + host + ',' + exit),
  // 此处插入经验证的 Claude 进程规则，覆盖其余外网 TCP。
  'GEOSITE,category-ads-all,REJECT',
  'GEOSITE,private,DIRECT',
  'GEOIP,private,DIRECT,no-resolve',
  'GEOSITE,cn,DIRECT',
  'GEOIP,CN,DIRECT,no-resolve',
  'MATCH,' + exit
];
config['sub-rules'] = {};
```

第一版建议采用保守的「拒绝进入 Mihomo 路由层的 UDP」策略，统一放在最前。影响包括 QUIC/HTTP3、部分通话、游戏及其他 UDP 应用；网页 TCP 访问与内核自身 DNS 连接需分别验证。此策略不代表阻止了操作系统中所有 UDP。

如果后续需要保留普通国内 UDP，必须形成单独策略并验证对受保护进程的精确识别，不能直接把国内放行规则移到保护阻断前面。

HTTP3 不可用后应用是否回退 TCP，由应用决定；不能将所有业务兼容性视为已通过。广告拒绝可以保留为通用功能，不依赖 stun 关键词实现完整防漏。

### 6.2 前跳和最终出口

前跳组只容纳本模式允许的传输节点，不将固定出口自身、保护组或未经检查的循环依赖纳入。无有效前跳时拒绝，不补 DIRECT。

providers 只有在加载成功且所选具体节点可用后才能进入可启动状态。前跳健康检查只证明前跳可达；另用受控中立端点验证完整链路及真实住宅出口。

最终出口不允许普通机场回退。住宅认证失败、住宅不可达、前跳故障时应请求失败，而非选择其他最终出口。

应用进程规则优先于国内直连规则，使受保护应用访问新增域名或直接 IP 时也不因地理分类绕行。进程路径、辅助进程与 Antify 转发后的进程归属均需实际验证；不要笼统匹配所有 node、python 或 Terminal 进程。

## 7. DNS 建议

保留 fake-IP 与 IPv6 关闭思路。按已确认的需求，国内网站的连接和 DNS 解析均可直连，不使用住宅出口。将解析分成三类：

| 类别 | 示例用途 | 目标路径 |
| --- | --- | --- |
| 节点引导解析 | 获得前跳入口域名的地址 | 明确配置的引导 DoH，DIRECT，不能依赖尚未建立的固定出口 |
| 国内与私网解析 | 国内普通网站、已批准的本地目标 | 国内解析器经 DIRECT；企业和局域网专用解析按显式例外配置 |
| 保护对象与其他海外解析 | Claude 及普通海外网站域名 | DoH 经固定出口；失败不回退国内解析器 |

保护域名使用显式域名策略，国内分类使用独立策略；不能用 JavaScript 对象的书写先后顺序作为 DNS 策略优先级的证明。必须在目标 Mihomo 版本验证精确保护域名与分类规则重叠时的行为，确认保护解析不会转到 DIRECT。[3]

住宅出口故障时，已明确归入国内直连分支的普通网站及其 DNS 应继续可用；Claude 和海外分支请求失败。未收录、仅凭目标 IP 地理分类的域名，其首次解析是否仍依赖海外 DNS，需要单独验证或补入受控国内域名清单，不能承诺所有国内服务都已覆盖。

下面是同一生成器内部的 DNS 草案。`settings.domains` 与 `exit` 沿用前文，解析服务地址为候选配置；为简化审阅省略局域网特殊解析，不是可替代全机 DNS 审计的完整保证：

```javascript
const domesticDns = ['https://223.5.5.5/dns-query#DIRECT'];
const overseasDns = [
  'https://1.1.1.1/dns-query#' + exit,
  'https://8.8.8.8/dns-query#' + exit
];
const dnsPolicy = {
  'geosite:cn,private': domesticDns
};
settings.domains.forEach(host => {
  dnsPolicy['+.' + host] = overseasDns;
});
config.dns = {
  enable: true,
  listen: '127.0.0.1:1053',
  ipv6: false,
  'enhanced-mode': 'fake-ip',
  'fake-ip-range': '198.18.0.1/16',
  'fake-ip-filter': ['localhost', '+.lan', '+.local', '+.pool.ntp.org'],
  'respect-rules': true,
  'prefer-h3': false,
  'use-hosts': false,
  'use-system-hosts': false,
  'default-nameserver': domesticDns,
  'proxy-server-nameserver': domesticDns,
  'direct-nameserver': domesticDns,
  'direct-nameserver-follow-policy': true,
  'nameserver-policy': dnsPolicy,
  nameserver: overseasDns
};
```

此处使用 IP 形式的 DoH 地址减少引导依赖。解析服务可用性、TLS 证书与地址兼容性需验证，不设置跳过证书校验。若住宅服务器本身使用域名，还应验证其解析不会依赖自己。[3]

同时审阅顶层 hosts、旧的 nameserver-policy、fallback、direct-nameserver、DNS 代理节点及额外 listeners/tunnels；不允许订阅提供另一条未受控业务解析或转发路径。接入专属策略时，不能无条件清空用户明确批准的企业 DNS，先在生成器中建模例外。

127.0.0.1 上的 DNS 监听不会自动接管全机查询。TUN DNS 接管、系统解析及 Antify 转发方式都需要实测。Antify 官方说明，Kill Switch 阻断期间域名查询仍可能发出，因此本文不能宣称单靠 Antify 就已解决故障时 DNS 泄漏。[5]

## 8. Verge、Antify 和守护进程的结合

### 8.1 应用设置与最终运行配置

Verge 官方文档给出的处理链路为：订阅原文 → 应用设置 → 全局扩展配置 → 全局扩展脚本 → 订阅扩展配置 → 订阅扩展脚本 → 应用设置回写。[1]

因此，脚本内写 `mode: rule`、7897 或 IPv6 关闭不能代替设置页与内核核验。后续订阅扩展覆盖规则或 DNS 时必须显示保护异常。对于可控订阅，应避免添加覆盖保护字段的订阅扩展。

不依赖在全局 Merge 中添加旧式 prepend-rules。公共基础设置和动态脚本的字段归属应明确，避免彼此覆写。与仓库现有托管 Script.js 块组合时保留用户原有 main，但最终保护字段由同一个受控生成器负责；未知后置覆盖由运行期检查发现。

### 8.2 Antify

用户完成系统扩展与内容过滤器授权后，为受保护应用添加明确的 Proxy 规则，选择指向 `127.0.0.1:7897` 的本地代理，并开启该应用规则的 Kill Switch。按本方案关闭受保护规则中的 Direct on Failure（失败时直连）；未匹配应用的配置默认行为可以保持 Direct，国内外分流由 Mihomo 决定。配置默认 Direct 不得代替 Claude 的显式 Proxy 规则。

用户提供的 Kill Switch 界面说明：Antify 代理未运行或无法连接代理服务器时，会阻断已启用该功能的应用；Kill Switch 优先于 Direct on Failure，由系统内容过滤器执行，退出 Antify 或重启 Mac 后仍保持启用。这是产品界面描述，目标版本上的持久化与故障阻断仍需实际验收，不能把提示文本当作已通过记录。

Dashboard 的状态应分别判断：

| 界面状态 | 含义与处理 |
| --- | --- |
| `Antify Proxy Not Running`、显示 `Start` | Antify 代理尚未运行；核对代理与应用规则后，点击 Start 启动 |
| `Content Filter Enabled` | 内容过滤器已启用；不能据此认定 Antify 代理已运行、Claude 规则已开启 Kill Switch 或住宅出口正确 |
| `Default: Direct` | 未命中应用规则时采用的默认动作；确认 Claude 命中其显式 Proxy 规则 |
| 已启用 Kill Switch，但代理尚未运行 | 受保护应用应被阻断；先恢复并验证代理链路，不为恢复联网临时关闭保护 |

首次配置与日常启动顺序：

1. 启动 Clash Verge，核验最终模式为 rule、本地入口为 `127.0.0.1:7897`，保护规则及固定出口已正确加载。
2. 在 Antify 的 Proxies 中确认本地代理地址与协议；在 Rules 中为实际受保护应用选中该代理并开启 Kill Switch。
3. 在 Dashboard 点击 Start，确认 Antify 代理运行；用受控中立端点确认应用实际匹配规则、完整代理链路与出口。
4. 完成启动前检查后，才从受管入口启动 Claude。未来启动流程的实现不能改变第 8.3 节所述现有命令限制。

两层保护各自处理不同故障：

| 故障 | 主要保护责任 | 预期行为 |
| --- | --- | --- |
| Antify 代理未运行，或无法连接本地 7897 入口 | Antify Kill Switch | 阻断覆盖应用的新连接，不启用失败直连 |
| 本地 7897 仍可连接，但住宅认证失败或住宅不可达 | Mihomo 固定出口与无直连回退规则 | 业务请求失败，不转普通机场或 DIRECT |
| 本地 7897 仍可连接，但规则被改为 DIRECT、出口绑定错误 | 全局脚本及最终运行配置/出口核验 | 拒绝受管启动；运行期异常按监督策略处置，并记录检测时间窗口 |

Antify Kill Switch 不能仅凭本地端口可连判断后续出口是否正确，不能替代固定出口规则和守护核验。不要把授权成功、界面开关或端口可连当作路由成功。这里的阻断说明针对新连接；已有连接、DNS、重载和扩展异常的行为仍分别验收。

Claude 桌面辅助进程、Claude Code 的真实可执行文件、外部子进程需逐项验证。Antify 默认不会把所有外部子进程自动纳入应用规则；启用 spawned processes 也有适用范围，不能为整个终端盲目开启。[6]

网页使用普通浏览器时，域名规则只覆盖名单内目标。完整应用保护应使用经验证的专用浏览器实例，并明确它的其他网站也可能受代理或断网策略影响。

不把 Clash/Mihomo 本身纳入同一 Antify 代理规则，避免代理流量重新进入本地代理造成循环。实际应用识别仍以 Connections 及中立测试端点的结果为准。

### 8.3 一个守护进程

复用现有监督能力的设计，不另建多套重复巡检服务。实现前先明确桌面受管进程与 CLI 受管进程组的所有权，不按模糊进程名终止用户的全部终端或浏览器。

| 检查 | 通过条件 |
| --- | --- |
| 本地入口 | 实际监听与配置一致，为 127.0.0.1:7897 |
| 运行模式 | 内核为 rule；其他模式不允许报告受保护 |
| 最终规则 | 保护前缀、明确的 UDP 拒绝、直连白名单及代理兜底符合策略 |
| 固定出口 | 实际参数与用户绑定一致；名称相同不能代替内容一致 |
| 前跳 | 有可用节点，依赖链无回环，不通过普通节点绕过住宅出口 |
| DNS | 国内解析 DIRECT、保护对象及海外解析经固定出口，引导例外和最终策略符合预期 |
| 接管与 Antify | 代理实际运行；目标应用命中正确 Proxy 规则并启用 Kill Switch；授权、规则和故障阻断分别核验 |
| 真实出口 | 经受控中立端点核验的出口身份符合绑定；同国家不等于同出口 |

启动前全部必需检查通过，才允许从受管入口启动。运行期间发现异常时停止受管进程或拒绝新启动，记录脱敏原因；修复后重新验证，不能仅因端口恢复就自动报告保护已恢复。

周期检查有时间窗口。订阅更新/切换时，优先在可控操作入口先暂停受管进程、更新、核验再恢复；用户直接操作 Verge 的未受控切换仍可能在被发现前发生变化。若验收不能接受这个窗口，再评估专用入口或更强的独立策略，而非提前宣称零泄漏。

现有项目的 `code check --route antify` 属于有限只读检测，`code run --route antify` 当前拒绝启动。本方案是后续实现目标，不会因为写入文档就改变现有命令契约。

## 9. 后台模板与用户配置的交付

公共模板维护规则列表、DNS 策略、传输模板和策略版本。用户专属内容按选定拓扑生成：模式 A 为住宅 SOCKS5 凭据；模式 B 为受保护 VLESS 接入凭据。两者都是私密交付物。

首次导入后，本地保留上一次已验证的专属设置。普通订阅下载或切换只更新节点来源，不清空住宅绑定。不在每次 main() 执行时临时联网获取出口资料，避免把网络故障变成丢失保护配置。

公共模板更新与住宅出口重绑定分别展示。用户看到策略版本、绑定是否有效和验证时间即可，不在日志或截图中展示完整地址、密码、UUID 或私密订阅链接。更换供应商凭据或出口身份时必须重新验收。

如果本地私密配置位于用户目录，限制为当前用户可读。守护进程即使以 root 运行，也不得执行用户可写文件中的任意命令或以 root 求值第三方脚本；读取经校验的数据和内核状态即可。项目已有系统守护脚本继续使用 root 所有、用户不可写的部署位置。

## 10. 验收矩阵

以下均为待执行验收，不是已通过记录。先使用隔离 HOME、假订阅、假凭据、受控中立端点及临时测试配置；不修改维护者已安装代理与 Antify。真实 Claude 域名测试仍遵守现有暂停要求。

| 场景 | 期望结果 | 必要证据 |
| --- | --- | --- |
| 国内普通网站 | 命中允许的直连规则，正常访问 | 内核规则匹配、受控连接记录 |
| 海外普通网站 | 走固定出口，无海外 DIRECT 例外 | 出口校验及规则匹配 |
| 保护域名被新订阅设为 DIRECT | 本地保护优先；实际 TCP 仍走固定出口 | 最终 rules、连接及出口记录 |
| 新订阅为 MATCH,DIRECT 或 SUB-RULE 放行 | 不继承外部兜底和子规则放行 | 生成结果、内核结果及连接记录 |
| 切订阅/刷新订阅 | 重新注入固定出口，节点不丢失、不回环 | 连续受控请求、重载前后出口记录 |
| 无节点/只有 provider/空 provider | 可用 provider 正常工作；无来源则失败，不直连 | 各分支的选中节点及请求结果 |
| 固定住宅代理不可达或认证失败 | 连接失败，不回退普通机场或 DIRECT | 受控故障注入、接口抓包 |
| 端口仍可连，但出口或规则错误 | 守护发现异常并阻止/停止受管进程 | 脱敏告警、停止记录、窗口测量 |
| 全局脚本报错、Geo 数据缺失 | 明确异常，不把旧配置或原订阅当作已保护 | Verge 实际失败行为及受管启动结果 |
| 后置扩展覆盖、切 direct/global 模式 | 不报告保护通过，触发异常处置 | 内核读回、告警及连接记录 |
| Antify 代理未启动但内容过滤器已启用 | 已启用 Kill Switch 的测试应用新连接被阻断，未受管应用按默认规则处理 | 应用规则、Dashboard 状态及受控连接证据 |
| 关闭 Clash 或断开本地端口 | 验证 Antify 是否阻断新连接，不回退 DIRECT | Antify 状态与接口抓包 |
| Kill Switch 与 Direct on Failure 同时开启 | 仅在隔离测试配置验证 Kill Switch 优先，故障时不直连；正式保护配置关闭失败直连 | 受控故障注入及接口抓包 |
| 退出 Antify 或重启 Mac | 验证内容过滤器与应用 Kill Switch 策略保留；代理未就绪时受保护新连接被阻断 | 退出/重启前后规则、过滤器及连接证据 |
| DNS 正常及故障场景 | 国内解析直连，保护对象及海外解析经固定出口；失败无跨分支回退 | 受控域名查询及接口抓包 |
| 住宅出口故障时国内访问 | 已纳入国内分支的普通网站及新 DNS 查询继续可用；保护域名不转 DIRECT | 清空测试缓存后的国内访问、保护域名重叠策略与故障抓包 |
| WebRTC/STUN、UDP 443及非标准端口 | 被明确阻断或按单独批准的策略处理 | 多端口测试；无响应不能单独证明安全 |
| IPv6、直接 IP、辅助进程及 CLI 子进程 | 走受保护路径或被阻断，未覆盖项明示 | IPv4/IPv6 双栈与进程级测试 |
| Antify 退出、扩展异常、系统重启/唤醒 | 检查实际新连接阻断及恢复条件 | 故障记录、重启/恢复后的连接证据 |

不以一次 HTTP 204 健康检查、相同国家、STUN 无响应或界面开关开启代替验收。不在文档、日志或测试输出中记录真实住宅地址、凭据与账号数据。

## 11. 实施顺序与明确边界

1. 确定用户交付物的拓扑 A/B；完成 v2 生成器的受控规则、完整 DNS 和 provider 边界改造。
2. 在隔离测试中覆盖规则优先级、恶意/异常 DIRECT 例外、重复生成、缺失字段、provider 与回环。
3. 使用临时 Mihomo 核心做配置加载及受控端点验收，验证真实路径而不只校验 JSON/YAML。
4. 实现与现有监督器衔接的最终配置检查、异常处置及状态展示；不改维护者安装态。
5. 经另行授权后，在目标环境配置 Antify 和全局脚本，完成验收矩阵中实际相关的项目。

Antify 官方公开说明：Kill Switch 阻断期间应用的域名查询仍可能发出；扩展崩溃并重启过滤器时存在短暂新连接窗口。[5] 全局脚本也不是 Verge 最后一道写配置的步骤。[1]

因此，第一版可交付承诺是：在明确的应用覆盖、配置及组件正常条件下，固定出口不随普通订阅变化；异常时按已验证能力阻断并报告。未经验证，不承诺任意配置覆盖、第三方扩展崩溃、DNS 或重载瞬间绝对零泄漏。如硬性验收要求包含这些情形，应将其列为尚未满足的要求，再按测得缺口增补方案。

本文只新增方案文档，不授权安装、更新本机软件、修改系统设置、启用扩展、访问真实 Claude 服务、部署、提交或推送。

# 将公网订阅接到管理后台

本指南供后续部署 `vpn-host1` 时使用。当前本地后台可以生成公网格式的地址，生成成功不表示公网已接通。

## 准备私有配置和数据库

将仓库代码复制到服务器的独立目录。使用 SQLite backup 接口备份本机私有数据库，再通过受保护的传输迁移到服务器，数据库文件权限设为 `0600`，父目录设为 `0700`。数据库包括用户令牌的哈希、入口 UUID、家庭代理凭据和归档安装资料，不能重新建空库来代替迁移。

在服务器配置管理员账号的带盐密码哈希，参照 [README 的配置脚本](README.md#启动)。不要把管理员密码或完整订阅地址放入命令参数、Git 或访问日志。

## 监听本机端口并设置交付域名

在仓库根目录启动服务，并将同一命令交给服务器的进程管理器托管。

```bash
python3 -m server --db /var/lib/claude-switcher/subscriptions.db \
  --host 127.0.0.1 --port 8787 \
  --base-url https://sub.610247.xyz \
  --admin-auth-file /private/path/admin-auth.json
```

检查服务仅监听 `127.0.0.1:8787`。管理页通过 SSH 端口转发访问，避免将 `/admin` 和 `/api` 加到公开 Tunnel。

## 给现有 Tunnel 添加独立路由

只读检查发现，该域名目前有带路径条件的路由指向旧订阅服务 `127.0.0.1:18081`。保留旧规则及其原始路径，在它之前添加新后台专用的规则。下面只有新增规则，不是整个 Tunnel 配置。

```yaml
- hostname: sub.610247.xyz
  path: '^/sub/cs_[A-Za-z0-9_-]+/[A-Za-z0-9][A-Za-z0-9_.-]{0,63}\.yaml$'
  service: http://127.0.0.1:8787
```

`cs_` 前缀区分本项目新令牌与旧静态订阅服务。不要将所有 `/sub/` 请求都改到新后台，否则旧订阅可能中断。管理接口、上传资料和登录路径不应命中这条规则。应用前备份现有配置，并使用该机安装的 cloudflared 校验完整 ingress 配置及新旧路径匹配结果。

本地后台仍支持 `/s/<token>`。如果需要让历史公网 `/s/` 地址继续可用，单独配置只匹配 `/s/cs_...` 的兼容规则；旧的 `127.0.0.1` 地址在其他设备上仍指向该设备本身，需要先在交付页转换。

## 核验下载和用户实际出口

在私有测试用户上检查新格式的订阅下载，确认 HTTPS、YAML、禁止缓存响应头和预期出口响应头。核对旧静态订阅仍走原服务。不要把真实令牌 URL 写入浏览器截图、诊断日志或工单。

新后台登记的用户 UUID 和家庭代理路由还需要合并到现有 3X-UI 入站。公网订阅能下载不表示该用户已经能联网。完成对应云端配置后，从客户端验证连接和实际出口；管理服务不自动修改远端 Xray。

管理员登录后可通过订阅交付页或 `GET /api/subscriptions` 重新查阅后台保存的通用订阅（Clash）和小火箭订阅链接。新建、导入与轮换原子保存令牌和哈希；历史哈希记录不会自动轮换，需要使用“恢复已有地址”保存仍有效的旧链接。数据库与备份包含可恢复订阅令牌，按凭据保护。普通用户/IP API 与网关导出不回显订阅令牌。
